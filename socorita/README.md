# Socorita HR Management System

A modern, modular HR Management System built with **Go**, **templ**, and **PostgreSQL**. Designed as a **modular monolith** for maintainability and scalability.

## Features

### Core Modules

- **Base Module**: Companies, Departments, Job Positions, Shifts, Work Types, Holidays
- **Employee Module**: Complete employee lifecycle management, work information, bank details, emergency contacts
- **Attendance Module**: Time tracking, clock in/out, overtime management, late/early tracking
- **Leave Module**: Leave types, requests, approvals, multi-level approval workflows

## Tech Stack

- **Language**: Go 1.21+
- **Web Framework**: Native Go `net/http` (standard library)
- **Database**: PostgreSQL
- **ORM/Query Builder**: [sqlc](https://sqlc.dev/) - Type-safe SQL queries
- **UI Templates**: [templ](https://templ.guide/) - Type-safe Go templates
- **Migrations**: [golang-migrate](https://github.com/golang-migrate/migrate)
- **Configuration**: Environment variables with [godotenv](https://github.com/joho/godotenv)

## Architecture

### Modular Monolith Structure

```
socorita/
├── cmd/server/              # Application entry point
├── internal/                # Private application code
│   ├── base/               # Base module (companies, departments, etc.)
│   │   ├── handler/        # HTTP handlers
│   │   ├── service/        # Business logic
│   │   ├── repository/     # Data access (generated by sqlc)
│   │   └── model/          # Domain models
│   ├── employee/           # Employee module
│   ├── attendance/         # Attendance module
│   ├── leave/              # Leave module
│   ├── auth/               # Authentication & authorization
│   └── shared/             # Shared utilities
│       ├── database/       # Database connection
│       ├── config/         # Configuration
│       └── utils/          # Helper functions
├── db/
│   ├── migrations/         # SQL migration files
│   └── queries/            # SQL query files for sqlc
├── web/
│   ├── templates/          # templ template files
│   └── static/             # Static assets (CSS, JS, images)
├── go.mod
├── sqlc.yaml               # sqlc configuration
├── Makefile                # Build and dev tasks
└── README.md
```

### Module Pattern

Each module follows a clean architecture pattern:

```
module/
├── handler/     # HTTP layer - receives requests, returns responses
├── service/     # Business logic layer - validation, orchestration
├── repository/  # Data access layer (generated by sqlc)
└── model/       # Domain models and DTOs
```

## Getting Started

### Prerequisites

- **Go 1.21+**: [Download Go](https://golang.org/dl/)
- **PostgreSQL 14+**: [Download PostgreSQL](https://www.postgresql.org/download/)
- **sqlc**: `go install github.com/sqlc-dev/sqlc/cmd/sqlc@latest`
- **templ**: `go install github.com/a-h/templ/cmd/templ@latest`
- **golang-migrate**: `go install -tags 'postgres' github.com/golang-migrate/migrate/v4/cmd/migrate@latest`
- **(Optional) Air** for hot reload: `go install github.com/cosmtrek/air@latest`

Or install all tools at once:

```bash
make install-tools
```

### Database Setup

1. Create a PostgreSQL database:

```bash
createdb socorita_db
```

2. Copy the example environment file and configure it:

```bash
cp .env.example .env
```

Edit `.env` with your database credentials:

```env
DB_HOST=localhost
DB_PORT=5432
DB_USER=your_username
DB_PASSWORD=your_password
DB_NAME=socorita_db
DB_SSLMODE=disable
```

3. Run migrations:

```bash
make migrate-up
```

### Generate Code

Generate type-safe database queries with sqlc:

```bash
make sqlc
```

Generate templ templates (when you add template files):

```bash
make templ
```

### Running the Application

#### Development Mode (with hot reload)

```bash
make dev
```

#### Production Mode

```bash
make build
./bin/server
```

Or simply:

```bash
make run
```

### Accessing the Application

Once running, the application will be available at:

- **Main App**: http://localhost:8080
- **Health Check**: http://localhost:8080/health

## Database Migrations

### Create a New Migration

```bash
make migrate-create name=add_user_preferences
```

This creates two files in `db/migrations/`:
- `000XXX_add_user_preferences.up.sql` - Apply migration
- `000XXX_add_user_preferences.down.sql` - Rollback migration

### Run Migrations

```bash
make migrate-up
```

### Rollback Last Migration

```bash
make migrate-down
```

## Development

### Project Structure

#### Database Schemas

Database schemas are defined in `db/migrations/`:
- `000001_init_base_module.up.sql` - Base module tables
- `000002_init_employee_module.up.sql` - Employee module tables
- `000003_init_attendance_module.up.sql` - Attendance module tables
- `000004_init_leave_module.up.sql` - Leave module tables

#### SQL Queries

SQL queries for sqlc are defined in `db/queries/`:
- `companies.sql` - Company CRUD operations
- `departments.sql` - Department operations
- `employees.sql` - Employee operations
- `users.sql` - User/authentication operations
- `attendance.sql` - Attendance tracking operations
- `leave.sql` - Leave management operations

After modifying queries, run:

```bash
make sqlc
```

This generates type-safe Go code in `internal/shared/repository/`.

### Adding a New Module

1. **Create module structure**:
   ```bash
   mkdir -p internal/mymodule/{handler,service,repository,model}
   ```

2. **Create migration**:
   ```bash
   make migrate-create name=init_mymodule
   ```

3. **Define SQL schema** in `db/migrations/000XXX_init_mymodule.up.sql`

4. **Create SQL queries** in `db/queries/mymodule.sql`

5. **Generate code**:
   ```bash
   make sqlc
   ```

6. **Implement module**:
   - Define models in `model/`
   - Implement business logic in `service/`
   - Create HTTP handlers in `handler/`

7. **Register routes** in `cmd/server/main.go`

### Code Generation

#### sqlc

sqlc generates type-safe Go code from SQL queries. Configuration is in `sqlc.yaml`.

Benefits:
- ✅ Type-safe database queries
- ✅ Compile-time validation
- ✅ No ORM overhead
- ✅ Full SQL control

#### templ

templ generates type-safe HTML templates from Go code.

Create a template file `web/templates/example.templ`:

```go
package templates

templ Hello(name string) {
    <div>
        <h1>Hello, { name }!</h1>
    </div>
}
```

Generate:

```bash
make templ
```

Use in handlers:

```go
templates.Hello("World").Render(context.Background(), w)
```

## API Documentation

### Base Module

#### Companies

- `GET /api/companies` - List all companies
- `GET /api/companies/:id` - Get company by ID
- `POST /api/companies` - Create a new company
- `PUT /api/companies/:id` - Update a company
- `DELETE /api/companies/:id` - Delete a company (soft delete)

#### Departments

- `GET /api/departments` - List all departments
- `GET /api/departments/:id` - Get department by ID
- `POST /api/departments` - Create a new department
- `PUT /api/departments/:id` - Update a department
- `DELETE /api/departments/:id` - Delete a department

### Employee Module

- `GET /api/employees` - List all employees
- `GET /api/employees/:id` - Get employee by ID
- `POST /api/employees` - Create a new employee
- `PUT /api/employees/:id` - Update an employee
- `DELETE /api/employees/:id` - Delete an employee

### Attendance Module

- `GET /api/attendance` - List attendance records
- `POST /api/attendance/clock-in` - Clock in
- `POST /api/attendance/clock-out` - Clock out
- `GET /api/attendance/today` - Get today's attendance

### Leave Module

- `GET /api/leave/types` - List leave types
- `GET /api/leave/requests` - List leave requests
- `POST /api/leave/requests` - Create leave request
- `PUT /api/leave/requests/:id` - Update leave request status
- `GET /api/leave/balance` - Get employee leave balance
